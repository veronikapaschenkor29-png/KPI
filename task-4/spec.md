# Специфікація: UC_Borrow (task-4)

## 1. Призначення
Опис бізнес-процесу видачі книги як єдиної діаграми діяльності (activity-borrow).

## 2. Учасники (смуги)
Читач, Система, Бібліотекар (з task-2/usecase.puml).

## 3. Сутності даних
MEMBER, LIBRARIAN, BOOK_COPY, LOAN, RESERVATION.

## 4. Діаграма діяльності
Файл: activity.puml / activity.png. Паралельні перевірки боргів (LOAN) і примірника (BOOK_COPY) через паралельні гілки (fork/join). Ранні виходи для відмов. Смуги мінімізують переходи.

## 5. Сценарії S1-S4 (з S2a) (шляхи)
- S1 Успішна видача: борги (ні), ліміт (ні), примірник (так) → створити LOAN → кінець.
- S2 Бронювання: борги (ні), ліміт (ні), примірник (ні), погоджується (так) → створити RESERVATION → кінець.
- S2a Відмова бронювання: ... погоджується (ні) → скасувати → відмова → кінець.
- S3 Відмова через борги: борги (так) → відмова → кінець.
- S4 Відмова через ліміт: борги (ні), ліміт (≥5) → відмова → кінець.

## 6. Повідомлення читачу
Пропонується бронювання → отримати пропозицію → погоджується?

## 7. Розгалуження
Борги, ліміт 5, примірник (доступний / «на руках» / недоступний), погодження бронювання.

## 8. Обмеження
Без термінів STORE, PRODUCT, ORDER, REVIEW, CATEGORY, Seller, Customer, Anonymous, BOOK_GENRE. Без символу «—». Підписи дій до 35 символів.
