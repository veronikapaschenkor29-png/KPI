# Завдання 4: Бізнес-процес (Activity Diagram)

Мета: описати UC_Borrow як єдиний бізнес-процес з усіма сценаріями на одній діаграмі діяльності.

## Артефакти

- [activity.puml](activity.puml) - діаграма зі смугами, паралельними гілками, повідомленнями.
- [activity.png](activity.png) - рендер діаграми.

## Вхідні дані

- [../task-2/usecase.puml](../task-2/usecase.puml) - use case UC_Borrow.

## Як переглянути

Відкрити activity.png або activity.puml у PlantUML.

## Сценарії і шляхи

| Сценарій | Шлях (коротко) |
| :--- | :--- |
| S1 Успішна видача | паралельно: борги (ні) & примірник (так) → підтвердити → створити LOAN → кінець |
| S2 Бронювання | паралельно: борги (ні) & примірник (ні) → (погоджується: так) створити RESERVATION → кінець |
| S2a Відмова бронювання | паралельно: борги (ні) & примірник (ні) → (погоджується: ні) скасувати запит → відмова → кінець |
| S3 Відмова через борги | борги (так) → відмовити → кінець |
| S4 Відмова через ліміт | борги (ні) → ліміт (≥5) → відмовити → кінець |

Деталі: activity.puml.

## Критерії

- Одна форма (activity), декларативний опис.
- ≥1 розгалуження з вичерпними умовами.
- ≥1 fork/join (паралельні перевірки боргів і примірника).
- ≥1 повідомлення з показаною реакцією («Пропонується бронювання» / вузол «Отримати пропозицію бронювання»).
- Кожен сценарій = шлях.
- Lanes (Читач, Система, Бібліотекар) ⊆ учасники sequence; вузли даних (MEMBER, LIBRARIAN, BOOK_COPY, LOAN, RESERVATION) ⊆ сутності ER.
